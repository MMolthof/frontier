## Abweichungen und Annahmen
Additive Felder (brechen die Form aus 3.9 nicht): Fehlerobjekte tragen bei `fit.skill`/`ship.skill` zusätzlich `skillId`, bei `fit.hardpoints` `hardpoint` ('turret'|'launcher'); `mining.critChance`; `fitting/moduleList` akzeptiert optional `includeUnowned: true`; `fitting/unequip` liefert `destroyed`.
1. **Reihenfolge je Stat** (5.2 wörtlich): Basis → Rumpfboni (mul: 1 + perLevel·Stufe) → Rollenboni → Modul-`add` → `set` → Modul-`mul` (Penalty) → Skill-Effekte. Folge: Rumpfboni auf HP/Cap wirken nur auf die Basis, Skills (z. B. Hull Upgrades, Shield Management) auch auf Modul-HP. Bei reinen Multiplikator-Stats ist die Reihenfolge egal. Offene Frage 1.
2. **Stacking-Penalty** je Ziel: Gruppiert wird nach `stackingGroup` unter den Effekten, die auf das Ziel wirken (Waffe/Laser: Effekte ohne `appliesTo` plus die mit passender `moduleGroup`). So bestraft ein Gyrostabilisator (Projektil) keinen Heat Sink (Energie), `rig_weapon` (alle Turrets) stackt aber mit beiden. Sortierung nach |Stärke| absteigend, Gewicht `exp(-(i/2.67)^2)`; Faktor = Produkt der Einzelfaktoren `1 + (m−1)·w` (add: Summe `v·w`). Gegenläufige Effekte in einer Gruppe gibt es in den Daten nicht (einfachste Variante, eine Kette). Effekte ohne `stackingGroup` werden nie bestraft. Rumpf-/Rollen-/Skillboni nie.
3. **Skill-Effekte** `mul`: Faktor `1 + perLevel·Stufe` (wie `tools/validate-data.mjs`), `add`: `+perLevel·Stufe`. Effekt ohne `appliesTo` wirkt auf alles (Gunnery auf alle Turrets), mit `appliesTo.moduleGroup` nur auf diese Gruppe.
4. **Resistenz** = Basis + add-Summe (Module mit Penalty, Skills ohne), geklemmt auf 0…0,95. **EHP** = Σ Schicht-HP / (1 − Mittelwert der 4 Resists).
5. **PG/CPU:** Maximum = Schiffswert × `powergrid_bonus`/`cpu_bonus`, auf 2 Nachkommastellen gerundet (ebenso `used`). **Calibration** max = Schiff + Skill-add (`skill.rigging` +10/Stufe). Mining-Upgrades: CPU × `cpu_penalty_mining_upgrade` (Basis 1, Skill `mining_upgrades` −5 %/Stufe).
6. **DPS/Tick** = Schaden · `turret_damage`/`missile_damage` · `rof` / `cycleTicks` (Launcher: missile, sonst turret); `offense.rangeKm` = größte Waffenreichweite · `weapon_range`. **Mining** `m3PerTick` = Σ `yieldM3 · mining_yield(Gruppe) / (cycleTicks · mining_cycle)`, ohne Crit (`critChance` wird mitgeliefert; Crit würfelt A7). **Cap:** alle aktiven Module laufen gleichzeitig; Nachladen = `capacitor / cap_recharge_ticks`; `stableForTicks` = `null`, wenn stabil. `nav.warpTicksPerAu = 1 / (warp_speed · balance.travel.warpScale)`.
7. **Fehlerpriorität** `checkEquip`: not_docked → (unbekanntes Modul: no_module) → slot_type → slot_occupied → size → hardpoints → powergrid → cpu → calibration → skill → **no_module (nicht im Stationslager) zuletzt**, damit `moduleList` mit `includeUnowned` die technischen Gründe zeigt. Unbekannte `uid` und Schiff in anderer Station → `fit.not_docked`; Slot-Index außerhalb oder unbekannter Slot-Name → `fit.slot_type`; Ausbau eines leeren Slots → `fit.no_module`.
8. **Ausbau** verhindert, wenn das Schiff danach PG/CPU überschritte (z. B. Reaktorsteuerung/Energienetz-Rig); war es schon überlastet, bleibt Ausbau erlaubt. Damit bleiben Fittings nach Ein-/Ausbau gültig. Rig-Ausbau ohne `confirm:true`: `{ok:false, error:'fit.rig_confirm', needsConfirm:true}`, mit: Rig weg, nicht ins Lager.
9. **`fitting/moduleList`** listet standardmäßig nur Module mit Bestand im aktuellen Stationslager (wie EVE-Hangar), nicht ausrüstbare mit `check`-Grund; `check` wird gegen den ersten freien Slot-Index (sonst Index 0) des Typs gerechnet. `includeUnowned: true` listet den ganzen Katalog des Slot-Typs.
10. **`fitting/preview`** rechnet auch bei fehlschlagendem `check` die hypothetische Bilanz (bei belegtem Slot als Austausch); `moduleId:null` simuliert den Ausbau. `delta` enthält nur geänderte numerische Pfade (auf 1e-6 gerundet), ohne `errors`/`weapons`.
11. **Access:** `ctx.select('skills/level', {skillId})` und `ctx.select('travel/isDocked', {})` werden vor dem direkten Lesezugriff (`state.pilot.skills[id].level`, `state.pilot.location.dockedStationId`) versucht. Solange A11/A6 fehlen, meldet `game.select` den unbekannten Selektor einmalig per `onWarn` (harmlos). Die Docking-Station kommt immer aus `state.pilot.location.dockedStationId`; liefert `travel/isDocked` `false`, gilt der Pilot als nicht angedockt. Argumentform der Fremdselektoren ist eine Annahme (`{skillId}`); der Selektor darf Zahl oder `{level}` liefern.
12. **i18n:** Texte aus `data.i18n.de.strings["error.<code>"]`; vier Schlüssel fehlen noch, Rückfalltexte in `errors.js` (Change Request a4-1).
13. `damage` der Schiffe wird nicht angefasst (Change Request a4-2, Punkt 4).
