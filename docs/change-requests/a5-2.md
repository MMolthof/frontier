# Change Request A5-2
- Betroffener Abschnitt im MASTER_PLAN: 3.5 (View-API), 3.7 (Shell-Vertrag), 6.1 (Tokens), 6.7 (Barrierefreiheit)
- Problem (konkret, mit Beispiel):
  1. A3 war beim Bau der Fitting-Ansicht nicht im Repo; `js/ui/components/**` und `js/ui/shell/**` fehlen. Die Ansicht bringt deshalb eigene Platzhalter mit (`js/ui/views/fitting/components.js`).
  2. Unklar, wer `css/views/<id>.css` lädt. Die Ansicht hängt ihr Stylesheet selbst ein (`<link id="c-fit-css">`).
  3. `view.enabled(game)` liefert bei Nichtverfügbarkeit `{ enabled:false, reason }` (laut `js/types.js` erlaubt), sonst `true`. Der Router muss beide Formen verstehen.
  4. Toasts: Die Ansicht zeigt Erfolg/Fehler eigener Aktionen selbst (`role="status"/"alert"`); Event-Toasts (`skills/completed` …) bleiben beim Router.
  5. Token `--gold` (#a8700e) hat auf Weiß nur 4,21:1 Kontrast (< 4,5:1 laut 6.7). Betrifft jeden Text in Gold (z. B. ISK in der Statusleiste).
- Vorschlag (Feld/Action/Event exakt benannt):
  1. Nach dem Merge von A3: `components.js` auf A3-Komponenten umleiten (`statBar`, `resistMatrix`, `tabs`, `confirm`, `toast`, optional `slot-ring`); `index.js` bleibt unverändert, weil es nur aus `components.js` importiert.
  2. A3-Router lädt `css/views/<id>.css` selbst **oder** bestätigt, dass das Selbst-Einhängen bleibt (Doppeltes Laden ist ausgeschlossen).
  3. Router/Neocom behandeln `enabled()` als `boolean | {enabled, reason}` und zeigen `reason` als Tooltip.
  4. Router ruft `view.update` weiter nach jedem Tick/jeder Action auf; die Ansicht drosselt selbst auf ≤ 1×/s.
  5. Token `--gold` für Text abdunkeln (z. B. #8f5f0b ≈ 5,2:1) **oder** Gold nur für Flächen/Rahmen verwenden und einen eigenen Text-Token einführen. Die Fitting-Ansicht nutzt Gold nie für Text.
